---
title: IEnumerable & IEnumerator
---

The `shard.collections` library is built on two generic interfaces:
  `IEnumerable<T>` and `IEnumerator<T>`.
  Together they form the **iteration contract** that powers the
  `foreach` statement, generic algorithms, and every standard
  collection type.

## Summary

  `IEnumerable<T>` represents a readable sequence of elements of
  type `T`. `IEnumerator<T>` is the cursor
  that walks that sequence one element at a time. The `foreach`
  statement calls `GetEnumerator()`, then repeatedly calls
  `MoveNext()` and reads `Current` until the
  sequence is exhausted.

## Syntax

  Both interfaces are declared in the global namespace by the compiler. They are written
  exactly as shown here when used as parameter types, return types, or variable types.

// ienumerable_ienumerator.shard
```csharp
// Interface signatures (compiler-provided).
interface IEnumerable<T>
{
    func GetEnumerator() -> IEnumerator<T>;
}

interface IEnumerator<T>
{
    func MoveNext() -> bool;
    prop Current: T;
}
```

  The `foreach` statement uses the following syntax. The loop variable
  type may be explicit or inferred with `:`.

// foreach_syntax.shard
```csharp
foreach (item in source)
{
    // body
}
```

## Parameters / Arguments

  `IEnumerable<T>` members:

| Member | Parameters | Returns | Description |
| --- | --- | --- | ---
| `GetEnumerator()` |  | `IEnumerator<T>` | Returns a new enumerator positioned before the first element of the sequence. |

  `IEnumerator<T>` members:

| Member | Parameters | Returns | Description |
| --- | --- | --- | ---
| `MoveNext()` |  | `bool` | Advances the cursor to the next element. Returns `true` if a valid element is available; otherwise `false`. |
| `Current` |  | `T` | Gets the element at the current cursor position. Valid only after a successful `MoveNext()` call. |

  The `foreach` statement accepts these arguments:

  - **Loop variable** — A local variable name that receives the current element. The type is inferred from the enumerator's element type unless explicitly declared.
  - **Source expression** — Any expression whose type implements `IEnumerable<T>`. Arrays, lists, dictionaries, queues, stacks, and ranges are all valid sources.

## Returns

| Member | Return Value |
| --- | ---
| `GetEnumerator()` | `IEnumerator<T>` — a fresh cursor positioned before the first element. |
| `MoveNext()` | `bool` — `true` while elements remain; `false` when the sequence ends. |
| `Current` | `T` — the element at the current cursor position. |
| `foreach` | `void` — the statement itself produces no value. |

## Exceptions / Errors

  - **Type does not implement IEnumerable&lt;T&gt;** — Using `foreach` on a non-enumerable type or passing a non-enumerable argument to a parameter typed as `IEnumerable<T>` fails semantic analysis.
  - **Current before MoveNext** — Accessing `Current` before the first successful `MoveNext()` call, or after `MoveNext()` has returned `false`, yields undefined behavior. The standard enumerators return the underlying storage element at the internal index, which is typically `null` or the last valid value.
  - **Invalid generic type argument** — Passing a concrete element type that does not match the source's element type (for example, `IEnumerable<string>` for an `int[]`) produces a compile-time type mismatch error.

## Remarks

  **Compiler-provided interfaces.** `IEnumerable<T>`
  and `IEnumerator<T>` are defined as
  `InterfaceSymbol` instances in the compiler's standard type system,
  not in user code. This lets the compiler recognize them during semantic analysis before any
  library is loaded. Concrete collection types register their conformance with
  `Implements(...)` in the native library registration code.

  **Arrays are implicitly enumerable.** The primitive array type is made to
  implement `IEnumerable<T>` through a hidden
  `ArrayEnumerator<T>` class. No wrapping or boxing occurs; the
  compiler treats an array as directly compatible with `IEnumerable<T>`.

  **foreach lowering.** The compiler lowers `foreach (x in source)`
  to the following bytecode pattern:

<ol className="space-y-2 text-text-secondary list-decimal pl-5">
  <li>Evaluate `source`.</li>
  <li>Call `GetEnumerator()` and store the result in a hidden local.</li>
  <li>Loop: call `MoveNext()`; jump to the end if it returns `false`.</li>
  <li>Call the `Current` getter and assign the value to the loop variable.</li>
  <li>Execute the loop body, then jump back to step 3.</li>
</ol>

<Info>
The current emitter does not emit a `Dispose` call for the enumerator
  when the loop exits. Standard ShardScript enumerators are unmanaged structs or classes with
  no resources, so this is safe today. If you implement a custom enumerator that holds native
  resources, dispose it manually with a `defer` block.
</Info>

  **Interface dispatch.** When `GetEnumerator()` is called
  through a variable typed as `IEnumerable<T>`, the compiler emits
  `CALLINTERFACE`. The VM resolves the concrete implementation at runtime
  through the `InterfaceMethodMap`. Each collection type registers both
  the interface and its matching enumerator type during library loading.

  **Enumerators are independent cursors.** Calling `GetEnumerator()`
  twice on the same collection returns two independent cursors. Modifying the collection through
  its own methods while an enumerator is active does not invalidate the enumerator; the enumerator
  continues to walk the snapshot of backing storage it was created with. This means additions made
  after the enumerator was created will not appear in the enumeration.

## Examples

  **Basic foreach over List&lt;T&gt;.**

// list_foreach.shard
```csharp
using stdio;
using collections;

namespace demo;

public static func Main() -> void
{
    list: List<int> = new List<int>();
    list.Add(10);
    list.Add(20);
    list.Add(30);

    foreach (n in list)
    {
        print(n);
        print(" ");
    }
    println("");   // 10 20 30
}
```

  **Manual enumeration with IEnumerator&lt;T&gt;.** This is the exact pattern
  `foreach` compiles to.

// manual_enumerator.shard
```csharp
using stdio;
using collections;

namespace demo;

public static func Main() -> void
{
    list: List<int> = new List<int>();
    list.Add(7);
    list.Add(8);
    list.Add(9);

    e: IEnumerator<int> = list.GetEnumerator();
    while (e.MoveNext())
    {
        println(e.Current);   // 7, 8, 9 (one per line)
    }
}
```

  **Arrays as IEnumerable&lt;T&gt;.** Arrays can be assigned directly to an
  `IEnumerable<T>` variable or passed to generic functions.

// array_ienumerable.shard
```csharp
using stdio;
using collections;

namespace demo;

public static func Sum(source: IEnumerable<int>) -> int
{
    total: int = 0;
    foreach (n in source)
    {
        total = total + n;
    }
    return total;
}

public static func Main() -> void
{
    nums: int[] = [10, 20, 30];
    e: IEnumerable<int> = nums;

    println(Sum(e));   // 60
    println(Sum(nums));   // 60 (array implicitly implements IEnumerable<int>)
}
```

  **Enumerating a Dictionary&lt;K, V&gt;.** The enumerator yields
  `KeyValuePair<K, V>` values with public
  `Key` and `Value` fields.

// dictionary_foreach.shard
```csharp
using stdio;
using collections;

namespace demo;

public static func Main() -> void
{
    ages: Dictionary<string, int> = new Dictionary<string, int>();
    ages.Add("alice", 30);
    ages.Add("bob", 25);

    foreach (pair in ages)
    {
        println(pair.Key + " = " + pair.Value);
    }
    // Output:
    // alice = 30
    // bob = 25
}
```

  **Multiple independent enumerators.** Each call to
  `GetEnumerator()` produces a separate cursor.

// independent_enumerators.shard
```csharp
using stdio;
using collections;

namespace demo;

public static func Main() -> void
{
    list: List<int> = new List<int>();
    list.Add(1);
    list.Add(2);

    a: IEnumerator<int> = list.GetEnumerator();
    b: IEnumerator<int> = list.GetEnumerator();

    a.MoveNext();
    b.MoveNext();
    b.MoveNext();

    println(a.Current);   // 1
    println(b.Current);   // 2
}
```

  **Edge case: Current outside the valid window.** Always call
  `MoveNext()` before reading `Current`.

// current_safety.shard
```csharp
using stdio;
using collections;

namespace demo;

public static func Main() -> void
{
    list: List<int> = new List<int>();
    list.Add(100);

    e: IEnumerator<int> = list.GetEnumerator();

    // Current is undefined here; do not rely on it before MoveNext.
    if (e.MoveNext())
    {
        println(e.Current);   // 100
    }

    // Current is also undefined after MoveNext returns false.
    while (e.MoveNext())
    {
        // No more elements; loop body never runs.
    }
}
```

  **Common mistake: modifying the collection during enumeration.** The enumerator
  holds a reference to the backing storage that existed when it was created. Later additions are
  not reflected, and the loop may appear to skip new elements.

// modification_during_enum.shard
```csharp
using stdio;
using collections;

namespace demo;

public static func Main() -> void
{
    list: List<int> = new List<int>();
    list.Add(1);
    list.Add(2);

    // This enumerator captures the current backing array.
    foreach (n in list)
    {
        println(n);

        // The addition allocates a new backing array; the enumerator keeps walking the old one.
        if (n == 1)
        {
            list.Add(99);
        }
    }
    // Output: 1, 2 (99 is not printed by this loop)
}
```

<Warning title="Custom enumerators">
User-defined classes and structs cannot yet implement compiler-standard interfaces such as
  `IEnumerable<T>` or `IEnumerator<T>`
  from ShardScript source code. The interfaces are recognized, but explicit interface
  implementation and user-authored generic interface implementations are still being finalized.
  Today, custom enumeration is best achieved by returning a built-in collection type.
</Warning>

## Category Summary

| Feature | Members |
| --- | ---
| IEnumerable&lt;T&gt; | GetEnumerator() |
| IEnumerator&lt;T&gt; | MoveNext(), Current |
