---
title: Variables and Types
---

ShardScript is a **statically and strongly typed** language: every local binding has a type that is known at compile time and fixed for the rest of its lifetime. There are exactly two ways to introduce a variable — an explicit type annotation or type inference — and both produce the same compile-time guarantee. There is no `var` keyword and no C-style `Type name = value` syntax.

## Introduction

  A variable in ShardScript is a named slot that holds a value of a specific type. The compiler resolves the type during semantic analysis, allocates a slot on the method's evaluation stack, and emits bytecode that operates on that slot. Because the type is fixed at declaration, the runtime never has to guess what a variable contains: assignment compatibility, operator resolution, and method dispatch are all verified before the program runs.

## What it is

  ShardScript provides a small set of built-in primitive types. Most are value types that are copied on assignment; `string` is a reference type, and `void` is only used to mark the absence of a return value.

| Type | Kind | Description |
| --- | --- | ---
| `int` | Value | 64-bit signed integer. |
| `double` | Value | 64-bit IEEE 754 floating-point. |
| `bool` | Value | true or false. |
| `char` | Value | A single UTF-16 character literal ('A'). |
| `byte` | Value | Unsigned 8-bit integer. |
| `nint` | Value | Pointer-sized native integer. |
| `string` | Reference | Immutable UTF-16 string. |
| `void` | — | Absence of a value; used only as a return type. |

  There are only two valid local declaration forms. ShardScript is **name-first**: the identifier always appears before the type.

| Form | Meaning |
| --- | ---
| `name: Type = value;` | Explicit annotation. The compiler checks that value is assignable to Type. |
| `name := value;` | Type inference. The compiler derives the type from value and fixes it permanently. |
| `name = value;` | Not a declaration. This is reassignment of an already-declared variable. |
| `Type name = value;` | Rejected. C-style declarations are not valid syntax. |
| `var name = value;` | Rejected. The var keyword is not allowed. |

## When to use it

  Choose the form that makes the code easiest to verify at a glance. The two forms are semantically equivalent — the compiler generates the same bindings and type checks either way.

- Use `name: Type = value;` when the type carries meaning that the initializer does not show, such as an interface or base-class variable, or when you want to pin a narrower type than the expression would infer.

- Use `name := value;` when the type is obvious from the right-hand side, such as a literal, a constructor call, or a well-named factory method.

- Avoid either form for fields, parameters, or return types: fields use property-like or member syntax, parameters declare their type in a parenthesized list, and return types follow the `->` arrow.

## Remarks

  **Type inference is static.** The `:=` operator reads as "is defined as" and is shorthand for writing the type out by hand. The compiler resolves the type once, at the point of declaration, and that type is immutable. There is no dynamic re-typing, no `any` fallback for locals, and no implicit widening after the fact.

  **Reassignment preserves the declared type.** A variable can be reassigned as many times as needed, but every new value must be assignable to the original type. Assigning a string to an `int` variable, or a `double` to a `bool`, is a compile-time error.

  **Scoping is method-body.** A local variable is visible from its declaration point to the end of the enclosing method, constructor, lambda, or property accessor body. Re-declaring a name that already exists in the same body is an error. Nested blocks such as `if` or `while` bodies do not introduce a new scope in the current implementation, so a variable declared inside a block remains visible after the block ends.

  **Locals require an initializer.** A declaration without a value is rejected by the parser. If a variable truly needs to start empty, declare it with a suitable default value such as `0`, `false`, `""`, or `null` for a reference type.

<Info>
`:=` does not weaken the type system. `x := 10` is exactly as strongly typed as `x: int = 10`; the only difference is who wrote the type on the page.
</Info>

## Examples

  The following example shows every primitive declared with an explicit type. Explicit annotation is useful when the code needs to be explicit about storage width or when a reviewer should see the contract immediately.

// primitives.shard
```csharp
using stdio;

namespace demo;

public static func Main() -> void
{
    // Explicit type annotation for each primitive.
    count: int       = 42;
    pi: double       = 3.14159;
    flag: bool       = true;
    letter: char     = 'A';
    channel: byte    = 255;
    handle: nint     = 0;
    name: string     = "ShardScript";

    println(count);
    println(pi);
    println(flag);
    println(name);
}
```

  The same variables can be written with type inference. The compiler determines the type from the literal on the right, then locks it in place.

// inference.shard
```csharp
using stdio;

namespace demo;

public static func Main() -> void
{
    // Explicit type annotations for each primitive.
    count: int    = 42;
    pi: double    = 3.14159;
    flag: bool    = true;
    letter: char  = 'A';
    channel: byte = 255 as byte;   // cast to byte because the literal 255 is int
    name: string  = "ShardScript";

    println(count);
    println(pi);
    println(flag);
    println(name);
}
```

  Reassignment is allowed as long as the new value matches the original type. Changing the type after declaration is not.

// reassignment.shard
```csharp
using stdio;

namespace demo;

public static func Main() -> void
{
    // The type is fixed once declared.
    score: int = 100;
    score = 200;           // OK -- still int

    // score = "high";      // ERROR: string is not assignable to int

    // Explicit annotation enforces the same rule.
    label: string = "start";
    label = "finish";      // OK

    // label = 42;          // ERROR: int is not assignable to string

    println(score);
    println(label);
}
```

  Explicit annotation is especially valuable when you want a base type or interface on the left and a derived type on the right. Inference would pin the variable to the concrete type.

// explicit_interface.shard
```csharp
using stdio;

namespace demo;

interface IShape
{
    func Area() -> double;
}

public class Circle : IShape
{
    public Radius: double;

    public init(r: double)
    {
        this.Radius = r;
    }

    public func Area() -> double
    {
        return 3.14159 * this.Radius * this.Radius;
    }
}

public static func Main() -> void
{
    // Explicit annotation keeps the variable at the abstraction level.
    shape: IShape = new Circle(2.0);

    // Inference would make 'shape' a Circle instead.
    // shape := new Circle(2.0);

    println(shape.Area());
}
```

  Scoping is tied to the enclosing method or lambda body. The same name cannot be declared twice in the same body, but parameters and outer variables can be referenced by nested lambdas.

// scoping.shard
```csharp
using stdio;

namespace demo;

public static func Main() -> void
{
    outer: int = 10;

    if (outer > 0)
    {
        // This declaration is visible for the rest of Main,
        // not just inside the if block.
        inner: int = 20;
        println(inner);
    }

    println(outer);

    // inner is still in scope here because blocks do not create a new scope.
    println(inner);

    // int outer = 99;      // ERROR: a symbol named 'outer' already exists
}
```

  The two most common mistakes for developers coming from C, C++, C#, or Rust are using C-style type-first declarations and using the `var` keyword. Both are rejected by the parser with a clear diagnostic.

// invalid_forms.shard
```csharp
using stdio;

namespace demo;

public static func Main() -> void
{
    // Valid ShardScript declarations.
    count: int    = 10;
    greeting: string = "hello";

    // The forms below are invalid and will not compile.
    // int count = 10;          // ERROR: invalid syntax; use 'name: Type = value'
    // var count = 10;          // ERROR: invalid use of 'var'; use 'name: Type = value'
    // count: int;              // ERROR: local declarations require an initializer

    println(count);
    println(greeting);
}
```

<Warning>
Only `name: Type = value;` and `name := value;` are valid local declarations. A local declared without an initializer is also rejected — give it a default value, or use a member field if the value must be initialized later.
</Warning>
