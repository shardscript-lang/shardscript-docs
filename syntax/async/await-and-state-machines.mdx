---
title: Await and State Machines
---

The `await` keyword is the suspension point in an `async`
  method. When execution reaches `await`, the method returns control to the
  event loop, registers a continuation, and later resumes exactly where it left off. The compiler
  makes this possible by rewriting every `async` method into a state machine
  whose `MoveNext` method is driven by an integer `State`
  field.

## Introduction

  ShardScript runs asynchronous work on a single-threaded libuv event loop. An `async`
  method never blocks an OS thread while it waits for a timer, file, socket, or other background
  operation. Instead, it *suspends* at an `await` expression, stores its
  local state, and lets the loop process other work. When the awaited operation completes, the
  runtime calls the stored continuation, which re-enters the method and continues from the next
  statement.

  This behavior is implemented by the compiler, not by the runtime alone. Before bytecode is emitted,
  the `AsyncStateMachineLowering` pass transforms each eligible async method
  into a compiler-generated class. The original method body becomes a `MoveNext`
  method that switches on the current state, and every local variable that must survive a suspension
  is lifted into a field.

## What it is

  **Await is a unary operator.** It takes an awaitable expression on its right and
  either returns the awaitable's result immediately (if it is already completed) or suspends the
  current async method until the awaitable completes. The operand must implement the
  `async.IAwaitable` interface, which exposes a `GetAwaiter`
  method. The awaiter must implement `async.IAwaiter` with
  `IsCompleted`, `OnCompleted`, and
  `GetResult` members.

| Member | Purpose |
| --- | ---
| `IAwaitable.GetAwaiter()` | Returns an IAwaiter that tracks completion and produces the result. |
| `IAwaiter.IsCompleted` | True if the operation has already finished. |
| `IAwaiter.OnCompleted(IAsyncState)` | Registers the state machine so it is resumed when the operation completes. |
| `IAwaiter.GetResult()` | Returns the result of the completed operation. |

  **The state machine is the continuation.** When the compiler lowers an async method,
  it generates a private class that implements `IAsyncState`. That interface
  has a single member, `MoveNext()`, which the runtime invokes each time the
  method resumes. The generated class also stores:

  - A `State` integer that records which suspension point to continue from.
  - The `Task` or `ValueTask` object that represents the async method's own completion.
  - Lifted copies of every parameter and local variable that are live across an  `await`.
  - An optional `OuterThis` reference when the async method is an instance member.

  **Lowering is a three-pass pipeline.** `AsyncStateMachineLowering`
  runs after semantic analysis and before layout:

<ol className="space-y-2 text-text-secondary">
  - **Hoisting pass.** Nested awaits inside expressions, conditions, and return statements are rewritten as top-level statements with temporary variables. This keeps the subsequent passes simple and predictable.
  - **Analysis pass.** The rewritten body is scanned for await sites. For each site, the pass records the active `try` regions, the statement that follows the await, and any variable that receives the await result.
  - **Emission pass.** After layout assigns field and slot offsets, bytecode is emitted for the state-machine constructor, the factory method that creates it, and the  `MoveNext` body.
</ol>

## When to use it

  Use `await` whenever an async method must wait for an operation without
  blocking the event loop. Typical cases include timers, I/O, network calls, thread-pool offloads, and
  composing multiple async operations.

  - **Timers and delays.** `await Task.Delay(milliseconds)` yields cooperatively and resumes after the interval.
  - **I/O and sockets.** File and socket operations register libuv handles; the method suspends until data is ready.
  - **Composing async helpers.** Await another `async` method to reuse sequential asynchronous logic.
  - **Consuming results.** Await a `ValueTask<T>` to obtain the typed result when it becomes available.

<Info>
Await is only valid inside an `async` method. The compiler rejects
  `await` in synchronous methods such as `Main`. To block
  synchronously on an async operation, call `Task.Wait(task)` or
  `ValueTask.Wait(task)`.
</Info>

## Remarks

  **Suspension is cooperative and single-threaded.** When `await`
  is reached, the runtime checks `IsCompleted`. If the operation is already
  done, execution continues synchronously. Otherwise the runtime stores the state machine as the
  continuation on the awaiter, sets the state machine's `State` to the resume
  label, and returns from `MoveNext`. The libuv loop then processes other
  timers and I/O until the operation completes and calls `OnCompleted`.

  **Resumption reads the continuation field.** The runtime helper
  `ResumeContinuation` retrieves the stored `IAsyncState`,
  calls its `MoveNext` method, and the generated switch jumps to the correct
  resume label. The task is rooted by the event loop while suspended so the garbage collector cannot
  reclaim it.

  **Locals survive suspension as fields.** Any parameter or local variable whose value is
  needed after an `await` is copied into a field on the state machine before
  the method returns, and copied back into a local slot when `MoveNext`
  resumes. Variables that are no longer live after the await are not lifted, keeping the state machine
  small.

  **Exception handling is preserved across awaits.** If an `await`
  appears inside a `try` block, the analysis pass records the active try stack at
  the resume point. When the method resumes, the emitter restores the correct exception-handler
  context before executing the code that follows the await. If the awaited operation faults, the
  exception is propagated through the stored continuation and dispatched to the matching
  `catch` clause.

  **Loops and conditionals require enumerator hoisting.** A `foreach`
  or `for-in` loop that contains an `await` must store its
  enumerator in a state-machine field, because the enumerator object must survive across suspensions.
  The same applies to the loop variable and any condition expression that is evaluated after each
  iteration.

<Warning title="Expression-level awaits">
The compiler supports awaits inside expressions such as return values, conditions, and assignments,
  but it first rewrites them into top-level statements during the hoisting pass. Write awaits as
  separate statements when possible; it makes the generated state machine smaller and easier to
  diagnose if lowering fails.
</Warning>

<Warning title="Async lambdas">
The language supports `async` methods on classes and top-level functions.
  Async lambda expressions are recognized by the parser in some contexts, but full state-machine
  lowering for lambdas is still being stabilized. Prefer named async methods for production code until
  support is complete.
</Warning>

## Examples

  **Basic suspension and resume.** The simplest await yields the loop and resumes after a
  timer fires.

// basic_await.shard
```csharp
using stdio;
using async;

namespace demo;

public class Program
{
    public static async func DelayAndReport() -> Task
    {
        println("before await");
        await Task.Delay(100);
        println("after await");
    }

    public static func Main() -> void
    {
        task: Task = DelayAndReport();
        Task.Wait(task);
    }
}
```

  **Awaiting a result with ValueTask.** Await returns the underlying value once the
  operation completes.

// valuetask_await.shard
```csharp
using stdio;
using async;

namespace demo;

public class Program
{
    public static async func ComputeAsync() -> ValueTask<int>
    {
        await Task.Delay(10);
        return 42;
    }

    public static async func UseResultAsync() -> Task
    {
        value: int = await ComputeAsync();
        println(value + 1);
    }

    public static func Main() -> void
    {
        task: Task = UseResultAsync();
        Task.Wait(task);
    }
}
```

  **Await inside a loop.** Each iteration suspends independently. The loop variable and
  any condition state are preserved across suspensions.

// await_in_loop.shard
```csharp
using stdio;
using async;

namespace demo;

public class Program
{
    public static async func CountWithPauses() -> Task
    {
        i: int = 0;
        while (i < 3)
        {
            println(i);
            await Task.Delay(10);
            i = i + 1;
        }

        println("done");
    }

    public static func Main() -> void
    {
        task: Task = CountWithPauses();
        Task.Wait(task);
    }
}
```

  **Await inside conditionals.** Both branches of an `if/else` can
  contain awaits. The state machine records which branch was taken so it resumes at the correct
  statement.

// await_in_conditional.shard
```csharp
using stdio;
using async;

namespace demo;

public class Program
{
    public static async func ToggleAsync() -> Task
    {
        i: int = 0;
        while (i < 4)
        {
            if (i % 2 == 0)
            {
                println("even before");
                await Task.Delay(1);
                println("even after");
            }
            else
            {
                println("odd before");
                await Task.Delay(1);
                println("odd after");
            }

            i = i + 1;
        }

        println("done");
    }

    public static func Main() -> void
    {
        task: Task = ToggleAsync();
        Task.Wait(task);
    }
}
```

  **Nested awaits.** Awaiting an async method that itself awaits another operation works
  because each method has its own state machine. The outer continuation is registered on the inner
  task, and the inner continuation is registered on the timer or I/O handle.

// nested_await.shard
```csharp
using stdio;
using async;

namespace demo;

public class Program
{
    public static async func InnerAsync() -> ValueTask<int>
    {
        await Task.Delay(10);
        return 7;
    }

    public static async func OuterAsync() -> ValueTask<int>
    {
        await Task.Delay(10);
        inner: int = await InnerAsync();
        return inner * 2;
    }

    public static func Main() -> void
    {
        task: ValueTask<int> = OuterAsync();
        ValueTask.Wait(task);
        println(task.Result);
    }
}
```

  **Custom awaitable.** You can implement `IAwaitable` and
  `IAwaiter` to make any type awaitable. The example below completes
  synchronously, so `IsCompleted` returns `true` and no
  continuation is scheduled.

// custom_awaitable.shard
```csharp
using stdio;
using async;

namespace demo;

public class ImmediateAwaiter : IAwaiter
{
    private Result: int;

    public init(value: int)
    {
        this.Result = value;
    }

    public func IsCompleted() -> bool
    {
        return true;
    }

    public func OnCompleted(continuation: IAsyncState) -> void
    {
        // Already completed, so no continuation is needed.
    }

    public func GetResult() -> int
    {
        return this.Result;
    }
}

public class ImmediateAwaitable : IAwaitable
{
    private Value: int;

    public init(value: int)
    {
        this.Value = value;
    }

    public func GetAwaiter() -> ImmediateAwaiter
    {
        return new ImmediateAwaiter(this.Value);
    }
}

public class Program
{
    public static async func TestCustomAwaitable() -> Task
    {
        awaitable: ImmediateAwaitable = new ImmediateAwaitable(123);
        result: int = await awaitable;
        println(result);
    }

    public static func Main() -> void
    {
        task: Task = TestCustomAwaitable();
        Task.Wait(task);
    }
}
```

  **Exception handling across await.** Exceptions thrown by an awaited operation are
  delivered to the active `try` block in the awaiting method.

// await_exception.shard
```csharp
using stdio;
using async;

namespace demo;

public class Program
{
    public static async func FaultyDelay() -> Task
    {
        await Task.Delay(10);
        throw new RuntimeException();
    }

    public static async func CaughtAwait() -> Task
    {
        try
        {
            await FaultyDelay();
            println("unreachable");
        }
        catch (ex: RuntimeException)
        {
            println("caught inside async");
            await Task.Delay(10);
            println(ex.message);
        }

        println("after catch");
    }

    public static func Main() -> void
    {
        task: Task = CaughtAwait();
        Task.Wait(task);
    }
}
```

  **Common mistakes.** These patterns are rejected by the compiler or produce surprising
  behavior.

// await_mistakes.shard
```csharp
using stdio;
using async;

namespace demo;

public class Program
{
    public static async func FireAndForget() -> Task
    {
        await Task.Delay(10);
        println("fires later");
    }

    public static func Main() -> void
    {
        // This starts the async method but does not wait for it.
        // The program may exit before "fires later" is printed.
        FireAndForget();

        // Correct: capture the task and wait.
        task: Task = FireAndForget();
        Task.Wait(task);
    }
}
```

<Warning title="Await outside async">
Writing `await Task.Delay(100);` inside a synchronous method such as
  `Main` produces a compile error. Use `Task.Wait(task)`
  to bridge sync and async code.
</Warning>

<Warning title="Forgetting to wait">
Calling an async method without awaiting or waiting on the returned task starts it concurrently but
  gives no guarantee it completes before the program exits. Always wait on the returned task unless
  the runtime explicitly keeps it alive.
</Warning>
