---
title: Generic Types
---

## Summary

  Generic types and methods let classes, structs, methods, delegates, and extension
  methods operate on a placeholder type `T` instead of a fixed
  concrete type. The compiler substitutes the placeholder with the requested type
  arguments at compile time, and the runtime creates a distinct layout for every
  concrete instantiation.

## Syntax

  Generic declarations introduce one or more type parameters inside angle brackets.
  The same syntax is used for classes, methods, delegates, and extension methods.

| Construct | Syntax |
| --- | ---
| **Generic class** | `{'public class Name<T> { ... }'}` |
| **Generic method** | `{'public func Name<T>(p: T) -> T { ... }'}` |
| **Static generic method** | `{'public static func Name<T>(p: T) -> T { ... }'}` |
| **Generic delegate** | `{'public delegate Name<T, U>(value: T) -> U;'}` |
| **Generic extension method** | `{'public static func Name<T>(this: T) -> T { ... }'}` |
| **Type application** | &#123;`{'Name<int>'}`&#125; or &#123;`{'obj.Method<int>()'}`&#125; |

  Multiple type parameters are separated by commas. Nested generic types are written by
  applying type arguments to a type argument, for example
  `Container<Container<int>>`.

## Parameters / Arguments

  Type parameters are declared on the type or method and are scoped to that declaration.
  Type arguments are the concrete types supplied when the generic is used.

  - **Type parameter** — A placeholder identifier such as `T`, `K`, or  `V`. It can appear in field types, parameter types, return types, and local variable types inside the declaration.
  - **Type argument** — A concrete type supplied inside angle brackets, for example `int`,  `string`, or `List<double>`. The argument count must exactly match the parameter count.
  - **Inference candidate** — For method calls, the compiler can infer type arguments from the types of the supplied value arguments. Inference is not available for class instantiations; you must write the type arguments explicitly.

## Returns

  A generic method or property returns the type that results from substituting the type
  arguments into the return-type expression. For example, a method declared as
  `func Make<T>(v: T) -> Container<T>` returns
  `Container<int>` when called with `T = int`.

## Exceptions / Errors

  - **Wrong number of type arguments** — Supplying `Container<int, string>` for a single-parameter class produces a compile error.
  - **Cannot infer type arguments** — If the arguments do not provide enough information to determine every type parameter, the compiler reports an inference failure and you must supply the type arguments explicitly.
  - **Type mismatch in inferred call** — When inference succeeds, every use of the type parameter must be consistent. Passing an `int` to a parameter of type `T` and a `string` to another parameter of type `T` fails because `T` cannot be both.
  - **Generic entry point** — A class that contains the program entry point `Main` must not itself have type parameters.
  - **Invalid operation on type parameter** — Because type parameters are unconstrained, you cannot perform arithmetic, equality tests, or member access on a value of type `T` unless the concrete type argument happens to support it and the compiler can prove it.

## Remarks

  **Reified layouts versus shared bytecode.** ShardScript generics are a
  hybrid. Every distinct instantiation such as `Container<int>`
  and `Container<string>` receives its own
  `TypeShape` and field layout at runtime, so value types are stored
  inline and reference types are stored as pointers. The bytecode for the generic method
  bodies, however, is emitted once per declaration. At runtime the VM passes the concrete
  type arguments in the call frame or derives them from the receiver object’s shape, then
  uses them for allocation and method dispatch. This gives the memory characteristics of
  reified generics while keeping the compiled image compact.

  **Type inference.** When you call a generic method without supplying type
  arguments, the compiler compares the declared parameter types against the arguments you
  passed and solves for the type parameters. Inference works for single arguments, multiple
  arguments, generic return types, array types, and nested generic types. If the compiler
  cannot determine every parameter, or if the solution would be inconsistent, you must
  provide the type arguments explicitly.

  **Generic methods on non-generic classes.** A plain class can declare a
  generic method. The method’s own type parameters are independent of any type parameters
  on the containing class. This is the typical pattern for factory helpers and generic
  extension methods.

  **Generic extension methods.** Extension methods can introduce their own
  type parameters. The first parameter is the receiver and may itself be generic. The call
  syntax uses the receiver value followed by the method name and type arguments, for example
  `value.Identity<int>()`.

  **Generic delegates.** A delegate type may declare type parameters and use
  them in its parameter list and return type. Lambda expressions and named functions that
  match the instantiated signature can be assigned to the delegate.

  **Nested generic types.** You can use an already-generic type as a type
  argument to another generic type. The compiler resolves the nesting left to right, and
  the runtime builds a separate shape for the fully constructed type.

<Info title="Generic constraints are supported">
ShardScript supports `where` clauses that restrict a type
  parameter to an interface, class, or struct type. See
  `Generic Constraints` for the syntax, examples, and
  limitations.
</Info>

## Examples

  **Generic class with a single type parameter.**

// generic_container.shard
```csharp
using stdio;

namespace demo;

public class Container<T>
{
    public Value: T;

    public func Set(v: T) -> void
    {
        // Store the caller-supplied value in the generic field.
        this.Value = v;
    }

    public func Get() -> T
    {
        return this.Value;
    }
}

public static func Main() -> void
{
    c: Container<int> = new Container<int>();
    c.Set(42);
    println(c.Get());        // 42

    d: Container<string> = new Container<string>();
    d.Set("hello");
    println(d.Get());        // hello
}
```

  **Multiple type parameters.**

// generic_pair.shard
```csharp
using stdio;

namespace demo;

public class Pair<K, V>
{
    public Key: K;
    public Value: V;
}

public static func Main() -> void
{
    p: Pair<int, string> = new Pair<int, string>();
    p.Key = 1;
    p.Value = "one";

    println(p.Key);          // 1
    println(p.Value);        // one
}
```

  **Generic method on a non-generic class.**

// generic_factory.shard
```csharp
using stdio;

namespace demo;

public class Factory
{
    public static func Make<T>(v: T) -> Container<T>
    {
        c: Container<T> = new Container<T>();
        c.Value = v;
        return c;
    }
}

public class Container<T>
{
    public Value: T;
}

public static func Main() -> void
{
    // Type inference: T is int because the argument is int.
    a: Container<int> = Factory.Make(42);
    println(a.Value);        // 42

    // Explicit type arguments are also allowed.
    b: Container<string> = Factory.Make<string>("hi");
    println(b.Value);        // hi
}
```

  **Generic instance method inside a generic class.**

// generic_class_method.shard
```csharp
using stdio;

namespace demo;

public class Container<T>
{
    public Value: T;

    public func Set(v: T) -> void
    {
        this.Value = v;
    }

    public func Get() -> T
    {
        return this.Value;
    }

    // U is independent of the class type parameter T.
    public func As<U>() -> Container<U>
    {
        result: Container<U> = new Container<U>();
        return result;
    }
}

public static func Main() -> void
{
    c: Container<int> = new Container<int>();
    c.Set(42);
    println(c.Get());        // 42

    e: Container<string> = c.As<string>();
    e.Set("converted");
    println(e.Get());        // converted
}
```

  **Nested generic types.**

// generic_nested.shard
```csharp
using stdio;

namespace demo;

public class Container<T>
{
    public Value: T;
}

public static func Main() -> void
{
    // The outer container stores another Container<int>.
    outer: Container<Container<int>> = new Container<Container<int>>();
    inner: Container<int> = new Container<int>();
    inner.Value = 99;
    outer.Value = inner;

    println(outer.Value.Value);   // 99
}
```

  **Generic extension method.**

// generic_extension.shard
```csharp
using stdio;

namespace demo;

public static func Identity<T>(x: T) -> T
{
    return x;
}

public static func Duplicate<T>(x: T) -> List<T>
{
    result: List<T> = new List<T>();
    result.Add(x);
    result.Add(x);
    return result;
}

public class List<T>
{
    private count: int;

    public func Add(item: T) -> void
    {
        this.count = this.count + 1;
    }

    public func GetCount() -> int
    {
        return this.count;
    }
}

public static func Main() -> void
{
    a: int = 5;
    b: int = a.Identity<int>();
    println(b);              // 5

    c: List<int> = a.Duplicate<int>();
    println(c.GetCount());   // 2
}
```

  **Generic delegate.**

// generic_delegate.shard
```csharp
using stdio;

namespace demo;

public delegate Transform<T, U>(value: T) -> U;

public static func Make<T, U>(action: Transform<T, U>) -> Transform<T, U>
{
    return action;
}

public static func Main() -> void
{
    addTen: Transform<int, int> = Make<int, int>(lambda (a: int) -> int
    {
        return a + 10;
    });

    println(addTen(5));      // 15
}
```

  **Type inference with arrays and nested generics.**

// generic_inference.shard
```csharp
using stdio;

namespace demo;

public static func First<T>(source: T[]) -> T
{
    // The caller is expected to pass a non-empty array.
    return source[0];
}

public static func MakeContainer<T>(v: T) -> Container<T>
{
    c: Container<T> = new Container<T>();
    c.Value = v;
    return c;
}

public class Container<T>
{
    public Value: T;
}

public static func Main() -> void
{
    nums: int[] = [10, 20, 30];

    // T is inferred as int from the int[] argument.
    first: int = First(nums);
    println(first);          // 10

    // T is inferred as string from the string argument.
    wrapped: Container<string> = MakeContainer("boxed");
    println(wrapped.Value);  // boxed
}
```

  **Common mistakes.**

// generic_mistakes.shard
```csharp
using stdio;

namespace demo;

public class Container<T>
{
    public Value: T;
}

public static func Swap<T>(a: T, b: T) -> void
{
    // The body is intentionally empty; the signature is what matters here.
}

public static func Main() -> void
{
    // Correct: both arguments have the same inferred type.
    Swap(1, 2);

    // ERROR: T cannot be both int and string.
    // Swap(1, "two");

    // ERROR: Container has one type parameter, not two.
    // c: Container<int, string> = new Container<int, string>();

    // Correct: nested generic types need matching arity at every level.
    outer: Container<Container<int>> = new Container<Container<int>>();
}
```
