---
title: Exceptions and Error Handling
---

## Summary

  ShardScript exceptions transfer control from the point of failure to the nearest enclosing
  `catch` clause that can handle the thrown object. The language provides
  `try`/`catch` blocks, the `throw`
  statement, typed filters, bare `throw;` rethrow, and automatic
  defer unwinding during stack traversal.

## Syntax

Statement form — every `try` must have at least one
`catch` clause:

// exceptions_syntax.shard
```csharp
try
{
    // guarded statements
}
catch (variable: ExceptionType)
{
    // handler for ExceptionType and subtypes
}
catch (variable: IThrowable)
{
    // broadest handler; matches any IThrowable implementation
}

// Throw a new exception.
throw new RuntimeException();

// Rethrow the exception currently being handled.
throw;
```

  `throw` is also accepted as a prefix expression inside another expression,
  but the statement form is the idiomatic way to raise an error.

## Parameters / Arguments

| Element | Required | Type | Description |
| --- | --- | --- | ---
| `try` | yes | keyword | Opens the guarded block whose exceptions are eligible for the attached catches. |
| `catch` | yes (one or more) | keyword | Opens a handler clause. A try without at least one catch is a parser error. |
| `variable` | yes (per clause) | identifier | The local name bound to the caught object inside the handler body. |
| `ExceptionType` | yes (per clause) | type | The type filter. The type must implement `IThrowable`. Use `IThrowable` itself as the broadest filter. |
| `throw expression` | yes (statement) | IThrowable | An object implementing `IThrowable` to raise. |
| `throw;` | yes (rethrow) | none | Re-raises the active exception from inside a catch body. |

  **Catch clause matching order:**

  - Clauses are evaluated in source order; the first clause whose type filter matches the thrown object wins.
  - A typed catch matches the declared type and any subtype that implements the same interface or inherits from the declared class.
  - A catch typed as `IThrowable` matches every throwable object and should be placed last, after all more specific clauses.

## Returns

  A `try`/`catch` statement has no value. If the
  `try` block completes normally, execution continues after the last
  `catch`. If an exception is thrown and caught, execution continues after the
  matching `catch` body. If an exception is thrown and not caught, it propagates
  to the caller.

## Exceptions / Errors

  - **Try without catch** — A  `try` block with no following `catch` clause produces a parser error: "'try' statement must have at least one 'catch' clause".
  - **Catch without variable or type** — Every catch must declare both an exception variable and a type. Forms such as  `catch  `, `catch (ex)`, or  `catch { ex }` are rejected.
  - **Non-throwable catch type** — A catch type must implement `IThrowable`. Catching `int`,  `string`, `any`, or other unrelated types fails semantic analysis.
  - **Throwing a non-throwable** — The expression supplied to a `throw` statement must evaluate to an object implementing  `IThrowable`.
  - **Rethrow outside catch** — A bare  `throw;` compiles only inside a `catch` body where an active exception exists.
  - **Unhandled exception** — If an exception reaches the entry point without being caught, the VM terminates and prints the stack trace captured at the throw site.

## Remarks

  **The `IThrowable` interface.** ShardScript defines a built-in
  interface `IThrowable` in the global namespace. It declares two read-only
  instance properties:

  - `message: string` — A human-readable description of the error.
  - `stack_trace: string` — The call-stack snapshot captured when the exception was thrown.

  Any class or struct that implements `IThrowable` can be thrown and caught.
  The built-in `RuntimeException` class implements the interface and is the
  conventional base for ad-hoc failures. Its default constructor takes no arguments; the
  `message` and `stack_trace` properties are populated by
  the runtime when the object is thrown.

  **Auto-population of `stack_trace`.** When a managed object that
  implements `IThrowable` is thrown with `throw`, the VM
  checks whether its `stack_trace` backing field is empty. If it is, the VM writes
  the current managed call stack into that field before control transfers to the handler. This makes
  managed throws consistent with exceptions raised from native code.

  **Typed exceptions from native libraries.** Native libraries can register their own
  `IThrowable` classes and throw them through
  `shard::runtime_exception`. The VM catches the C++ exception and instantiates the
  requested managed type instead of the built-in `RuntimeException`. See the
  `library-building/throwing-typed-exceptions` how-to for the full registration and
  throw pattern.

  **Typed versus broad handlers.** Use typed catches for code paths that need to
  inspect a specific failure. Use `catch (ex: IThrowable)` as the final
  safety net; it matches every throwable object and binds the variable as the interface type.
  Because matching is sequential, always place the most specific types first and the broadest
  handler last.

  **Flow-analysis warnings.** The compiler's flow analyzer tracks which exception types
  may escape from each method, constructor, accessor, and operator. When a call site is not inside
  a `try/catch` that can catch every thrown type, the compiler emits a warning:

```text
Call to 'Thrower' may throw 'RuntimeException'
```

  If the callee may throw but its specific type set is unknown, the warning falls back to:

```text
Call to 'Thrower' may throw an exception
```

  Wrapping the call in a `try/catch` with a matching filter — exact type, base
  class, or `IThrowable` — removes the warning for the caught types. Warnings are
  printed during normal compilation and `--lint`.

  **Rethrow semantics.** Inside a catch body, `throw;` re-raises
  the exception currently being handled, preserving the original stack trace. This is different from
  `throw ex;`, which would create a new throw point and overwrite the trace.
  Use `throw;` when you only want to log or partially handle an error before
  passing it up the stack.

  **Stack unwinding and `defer`.** When an exception is thrown, the
  VM walks the call stack looking for a handler. Before entering each candidate
  `catch`, it drains every `defer` registered in the
  scopes being unwound, in last-in, first-out order. If no handler exists in the current frame, all
  remaining defers in that frame run before the exception propagates to the caller. See the
  `defer` reference page for full details on scope boundaries and resource
  cleanup.

  **Async methods.** Exceptions thrown inside an `async` method are
  captured by the returned `Task` or `ValueTask` and
  re-thrown when the task is awaited or when `Wait()` is called.
  `try`/`catch` works around `await`
  because the async state-machine lowering preserves exception-handler offsets across suspension
  points.

  **VM lowering.** The compiler emits `ENTER_TRY` to register a
  handler, `LEAVE_TRY` when the guarded block exits normally, and
  `END_CATCH` at the end of the handler region. Each typed catch emits an
  `IS_INSTANCE` check followed by a conditional jump; if no clause matches, the
  runtime falls through to `THROW` to continue propagation.

<Warning title="finally blocks are not implemented">
ShardScript does not yet support `finally` blocks. Use
  `defer` inside the `try` block for deterministic
  cleanup that runs on both normal exit and exception unwinding.
</Warning>

## Examples

  **Basic try/catch with RuntimeException.**

// basic_try_catch.shard
```csharp
using stdio;

namespace demo;

public static func Main() -> void
{
    try
    {
        println("before throw");
        throw new RuntimeException();
    }
    catch (ex: RuntimeException)
    {
        println("caught RuntimeException");
    }

    println("after catch");
}
```

Expected output:

// output.txt
```plaintext
before throw
caught RuntimeException
after catch
```

  **Typed catches and the IThrowable base handler.**

// typed_catches.shard
```csharp
using stdio;

namespace demo;

public class NetworkException : RuntimeException


public class TimeoutException : NetworkException


public static func Simulate(code: int) -> void
{
    if (code == 1)
    {
        throw new TimeoutException();
    }
    else if (code == 2)
    {
        throw new NetworkException();
    }
    else
    {
        throw new RuntimeException();
    }
}

public static func Main() -> void
{
    for (code: int in 1..4)
    {
        try
        {
            Simulate(code);
        }
        catch (ex: TimeoutException)
        {
            println("timeout");
        }
        catch (ex: NetworkException)
        {
            println("network error");
        }
        catch (ex: IThrowable)
        {
            println("generic throwable");
        }
    }
}
```

Expected output:

// output.txt
```plaintext
timeout
network error
generic throwable
```

  **Rethrow to preserve the original failure.**

// rethrow.shard
```csharp
using stdio;

namespace demo;

public static func LogAndForward() -> void
{
    try
    {
        throw new RuntimeException();
    }
    catch (ex: RuntimeException)
    {
        // Log locally, then continue propagating the same exception.
        println("logged");
        throw;
    }
}

public static func Main() -> void
{
    try
    {
        LogAndForward();
    }
    catch (ex: RuntimeException)
    {
        println("caught after rethrow");
    }
}
```

Expected output:

// output.txt
```plaintext

caught after rethrow
```

  **Inspecting the stack trace.**

// stack_trace.shard
```csharp
using stdio;

namespace demo;

public static func Inner() -> void
{
    throw new RuntimeException();
}

public static func Outer() -> void
{
    Inner();
}

public static func Main() -> void
{
    try
    {
        Outer();
    }
    catch (ex: RuntimeException)
    {
        println("message: " + ex.message);
        println("stack trace:");
        println(ex.stack_trace);
    }
}
```

Expected output (exact frame names depend on your namespace):

// output.txt
```plaintext
message:
stack trace:
demo.Program.Outer
demo.Program.Inner
demo.Program.Main
```

  **Stack unwinding with defer.**

// defer_unwind.shard
```csharp
using stdio;

namespace demo;

public static func LevelThree() -> void
{
    defer println("level-three cleanup");
    println("level-three throwing");
    throw new RuntimeException();
}

public static func LevelTwo() -> void
{
    defer println("level-two cleanup");
    LevelThree();
}

public static func LevelOne() -> void
{
    defer println("level-one cleanup");
    LevelTwo();
}

public static func Main() -> void
{
    try
    {
        LevelOne();
    }
    catch (ex: RuntimeException)
    {
        println("caught in Main");
    }
}
```

Expected output:

// output.txt
```plaintext
level-three throwing
level-three cleanup
level-two cleanup
level-one cleanup
caught in Main
```

  **Async exception propagation.**

// async_exception.shard
```csharp
using stdio;
using async;

namespace demo;

public static async func Faulty() -> Task
{
    await Task.Delay(10);
    throw new RuntimeException();
}

public static func Main() -> void
{
    task: Task = Faulty();

    try
    {
        task.Wait();
    }
    catch (ex: RuntimeException)
    {
        println("async failure observed");
    }
}
```

Expected output:

// output.txt
```plaintext
async failure observed
```

  **Common mistake: catching a base type before a derived type.**

// catch_order_mistake.shard
```csharp
using stdio;

namespace demo;

public class BaseException : RuntimeException


public class DerivedException : BaseException


public static func Main() -> void
{
    try
    {
        throw new DerivedException();
    }
    // WRONG ORDER: BaseException matches first, so the more specific
    // DerivedException handler below is unreachable.
    catch (ex: BaseException)
    {
        println("base");
    }
    // catch (ex: DerivedException)
    // {
    //     println("derived");
    // }
}
```

<Info>
The commented-out `DerivedException` handler is unreachable because the
  preceding `BaseException` clause already catches the object. Always order
  catches from most derived to least derived, and put the broadest `IThrowable`
  handler last.
</Info>

  **Common mistake: using throw ex instead of throw.**

// throw_ex_mistake.shard
```csharp
using stdio;

namespace demo;

public static func Wrapper() -> void
{
    try
    {
        throw new RuntimeException();
    }
    catch (ex: RuntimeException)
    {
        // This compiles, but it resets the throw point and stack trace.
        // Prefer the bare 'throw;' rethrow shown earlier.
        throw ex;
    }
}

public static func Main() -> void
{
    try
    {
        Wrapper();
    }
    catch (ex: RuntimeException)
    {
        println("caught wrapper exception");
    }
}
```

## Runtime exception catalog

  The ShardScript virtual machine raises runtime exceptions when a guarded operation cannot complete
  safely. The catalog below lists the most common runtime error messages produced by the language
  itself, grouped by the operation that triggers them. Library-specific errors are documented on
  their respective standard-library pages.

| Operation | Typical message | Thrown type |
| --- | --- | ---
| Integer division by zero | DivideByZeroException | `RuntimeException` |
| Integer modulo by zero | DivideByZeroException | `RuntimeException` |
| Array index out of bounds | Array index is out of range: index=... length=... | `RuntimeException` |
| Indexer on null array | Cannot access indexer on null instance of type ... | `RuntimeException` |
| Member access on null reference | Cannot access member on null instance of type ... | `RuntimeException` |
| Method call on null reference | Cannot access member on null instance of type ... | `RuntimeException` |
| Null delegate invocation | Delegate is null | `RuntimeException` |
| Reflection on missing type | Type not found | `RuntimeException` |
| Reflection on null instance | cannot get type of null instance | `RuntimeException` |

  **DivideByZeroException.** Integer, character, byte, native-pointer, and enum
  division or modulo with a zero divisor throws `DivideByZeroException`.
  Floating-point division by zero does not throw; it follows IEEE-754 rules and may produce infinity.

  **Array index out of range.** Reading or writing an array element with an index
  outside `0 .. Length - 1` throws a message such as
  `Array index is out of range: index=... length=...`. Negative indices are
  treated as very large positive values because the index is cast to `std::size_t`
  before the bounds check.

  **Null indexer access.** Using the square-bracket indexer on a `null`
  array reference throws `Cannot access indexer on null instance of type ...`.

  **Null member access.** Reading a field or property on a `null`
  reference throws `Cannot access member on null instance of type ...`.

  **Null method call.** Calling an instance method on a `null`
  reference throws `Cannot access member on null instance of type ...`.

  **Null delegate invocation.** Calling a delegate variable that holds
  `null` throws `Delegate is null`.

  **Reflection failures.** Looking up a type by name that is not loaded throws
  `Type not found`. Inspecting the type of a `null`
  instance throws `cannot get type of null instance`.

  **Native extern returning null for a value type.** An extern method declared to return
  a value type that returns `nullptr` from native code throws
  `extern method '...' returned nullptr for value type`. Reference-type extern
  methods that return `nullptr` are mapped to the managed
  `null` instance instead.

<Warning>
Not every runtime failure produces a catchable exception today. Some low-level VM faults still
  terminate the process directly. Treat any error listed here as catchable, and treat unlisted
  failures as requiring defensive coding.
</Warning>

  **Catching division by zero.**

// divide_by_zero.shard
```csharp
using stdio;

namespace demo;

public static func Main() -> void
{
    try
    {
        x: int = 1 / 0;
        println(x);
    }
    catch (ex: RuntimeException)
    {
        println("caught: " + ex.message);
    }
}
```

  **Array bounds checking.**

// array_bounds.shard
```csharp
using stdio;

namespace demo;

public static func Main() -> void
{
    values: int[] = [10, 20, 30];

    try
    {
        println(values[3]);      // out of range
    }
    catch (ex: RuntimeException)
    {
        println("caught: " + ex.message);
    }

    try
    {
        empty: int[] = null;
        println(empty[0]);       // null indexer
    }
    catch (ex: RuntimeException)
    {
        println("caught: " + ex.message);
    }
}
```

  **Null instance member and method access.**

// null_access.shard
```csharp
using stdio;

namespace demo;

public class Box
{
    public Value: int;

    public func GetValue() -> int
    {
        return this.Value;
    }
}

public static func Main() -> void
{
    box: Box = null;

    try
    {
        println(box.Value);
    }
    catch (ex: RuntimeException)
    {
        println("caught member access");
    }

    try
    {
        println(box.GetValue());
    }
    catch (ex: RuntimeException)
    {
        println("caught method call");
    }
}
```

  **Null delegate invocation.**

// null_delegate.shard
```csharp
using stdio;

namespace demo;

public delegate Action() -> void;

public static func Main() -> void
{
    action: Action = null;

    try
    {
        action();
    }
    catch (ex: RuntimeException)
    {
        println("caught: " + ex.message);
    }
}
```

  **Message stability.** The messages in this catalog are representative of the current
  implementation. Minor wording changes may occur between releases, so production code should catch
  by exception type or by `RuntimeException` rather than by exact message
  string.
