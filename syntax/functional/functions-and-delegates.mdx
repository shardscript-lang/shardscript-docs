---
title: Delegates
---

## Summary

  A `delegate` is a named or inline function type that describes the parameter and return signature of a callable value. Delegates let functions be stored in variables, passed as arguments, returned from other functions, and invoked later.

## Syntax

  There are two ways to express a delegate type and two ways to create a delegate value.

| Form | Syntax | Usage |
| --- | --- | ---
| Named delegate declaration | `public delegate Name(params) -> ReturnType;` | Defines a reusable, named callable type. |
| Inline delegate type | `delegate ReturnType(ParamType, ...)` | A fabricated type written directly where a type is needed. |
| Lambda expression (explicit return) | `{'lambda (params) -> Type { body }'}` | Anonymous function with an explicit return type. |
| Lambda expression (inferred return) | `{'lambda (params) => { body }'}` | Anonymous function whose return type is inferred from the body. |
| Method-to-delegate conversion | `dlg: DelegateType = MethodName;` | Binds an existing named method to a delegate variable. |

  A named delegate is declared at namespace or type scope just like a class. An inline delegate type is written wherever a type appears: variable declarations, parameters, fields, and return types. The inline form lists only parameter *types*, not parameter names.

## Parameters / Arguments

| Element | Required | Description |
| --- | --- | ---
| Return type | Yes | The type the delegate evaluates to when invoked. Use `void` for actions. |
| Parameter list | Yes | A parenthesized, comma-separated list of typed parameters. Empty parentheses mean no parameters. |
| Generic type parameters | Optional | Named delegates may declare generic parameters, e.g. `delegate Transform<T, U>(value: T) -> U;`. |
| Access modifier | Optional | Named delegates support access modifiers such as `public` and `internal`. |

  When a named method is bound to a delegate, every parameter type and the return type must match exactly. The parameter *names* in the delegate declaration are not part of the signature for matching purposes, but they serve as documentation.

## Returns

| Construct | Result |
| --- | ---
| Delegate declaration | Defines a new callable type; it does not produce a runtime value. |
| Lambda expression | Evaluates to a delegate value that captures the anonymous method. |
| Method group conversion | Evaluates to a delegate value that targets the named method. |
| Delegate invocation | Evaluates to the return type declared by the delegate. |

## Exceptions / Errors

  - **Signature mismatch** — Assigning a lambda or method to a delegate whose parameter or return types differ produces a compile-time error.
  - **Missing `lambda` keyword** — A bare expression such as `(x) => x + 1` does not parse; the `lambda` keyword is mandatory.
  - **Async lambda without explicit return type** — An `async lambda` must declare an explicit return type such as `Task` or `ValueTask<T>`; the `=>` inferred form is not allowed.
  - **Null invocation** — Calling a delegate variable whose value is `null` throws a runtime null-reference exception.
  - **Argument count mismatch** — Invoking a delegate with too many or too few arguments fails at compile time.

## Remarks

  **Named versus inline delegate types.** A named delegate is useful when the same signature appears in many places or when you want a self-documenting type name. An inline delegate type is convenient for one-off callbacks and local variables. Both are functionally equivalent: a value of type `GetIntegerDelegate` can be assigned to a variable of type `delegate int(int)` only if the signatures match, and the compiler treats both as instances of the same underlying delegate machinery.

  **First-class functions.** Because delegates are values, you can pass them into methods, return them from methods, store them in fields, and place them in collections. The VM represents a delegate as a small object that holds a reference to the target method and, for instance methods, a receiver object. Static methods and lambdas produce delegates with no receiver.

  **Method group conversion.** When a method name appears in a context that expects a delegate type, the compiler creates a delegate that wraps the method directly. No explicit lambda wrapper is required. The conversion works for both static and instance methods, provided the signature matches.

  **Invocation syntax.** A delegate variable is invoked with ordinary call syntax: `myDelegate(arg1, arg2)`. The compiler rewrites the call to invoke the delegate's underlying `Invoke` method, which the runtime dispatches through the `CALLDELEGATE` opcode.

<Info>
ShardScript delegates currently hold a **single target**. Combining delegates with `+` or `+=` to create multicast delegates is not supported. If you need to call several handlers in sequence, iterate over a collection of delegates or invoke them explicitly.
</Info>

<Warning title="Async lambdas need an explicit return type">
Prefix a lambda with `async` to create a closure that can `await`. Because the async state machine must know the result type up front, you must write `async lambda (params) -> Task { ... }` or `async lambda (params) -> ValueTask<T> { ... }`. The inferred `=>` form is rejected for async lambdas.
</Warning>

## Examples

  **Named delegate, lambda, and method conversion.**

// named_delegate.shard
```csharp
using stdio;

namespace demo;

// A named delegate type, reusable across the codebase.
public delegate IntFunc(a: int) -> int;

static func Triple(x: int) -> int
{
    return x * 3;
}

public static func Main() -> void
{
    // Bind a lambda to the named delegate type.
    inc: IntFunc = lambda (a: int) -> int
    {
        return a + 1;
    };

    // Bind a named method directly -- no wrapper lambda needed.
    mult: IntFunc = Triple;

    println(inc(5));       // 6
    println(mult(4));      // 12
}
```

  **Inline fabricated delegate type.**

// inline_delegate.shard
```csharp
using stdio;

namespace demo;

static func Add(a: int, b: int) -> int
{
    return a + b;
}

public static func Main() -> void
{
    // An inline delegate type lists only parameter types, no names.
    op: delegate int(int, int) = Add;

    // A lambda also fits the inline type as long as signatures match.
    scale: delegate int(int) = lambda (x: int) -> int
    {
        return x * 10;
    };

    println(op(2, 3));      // 5
    println(scale(7));      // 70
}
```

  **Higher-order functions: passing and returning delegates.**

// higher_order.shard
```csharp
using stdio;

namespace demo;

public delegate IntFunc(a: int) -> int;

// A function that takes a delegate argument.
static func Apply(f: IntFunc, x: int) -> int
{
    return f(x);
}

// A function that returns a delegate.
static func Choose(op: int) -> IntFunc
{
    if (op == 0)
    {
        return lambda (a: int) -> int
        {
            return a + 1;
        };
    }

    return lambda (a: int) -> int
    {
        return a - 1;
    };
}

public static func Main() -> void
{
    // Pass a lambda directly where a delegate is expected.
    result: int = Apply(lambda (a: int) -> int { return a * a; }, 5);
    println(result);        // 25

    step: IntFunc = Choose(0);
    println(step(10));      // 11
}
```

  **Generic delegates.**

// generic_delegate.shard
```csharp
using stdio;

namespace demo;

public delegate Transform<T, U>(value: T) -> U;

static func Make<T, U>(action: Transform<T, U>) -> Transform<T, U>
{
    return action;
}

public static func Main() -> void
{
    f: Transform<int, int> = Make<int, int>(lambda (a: int) -> int
    {
        return a + 10;
    });

    println(f(5));      // 15
}
```

  **Edge cases and common mistakes.**

// delegate_edge_cases.shard
```csharp
using stdio;

namespace demo;

public delegate Predicate(x: int) -> bool;

static func CountWhere(items: int[], matches: Predicate) -> int
{
    count: int = 0;

    foreach (n: int in items)
    {
        if (matches(n))
        {
            count = count + 1;
        }
    }

    return count;
}

public static func Main() -> void
{
    threshold: int = 5;
    nums: int[] = [1, 6, 3, 9, 4];

    // A lambda captures 'threshold' from the enclosing scope.
    big: int = CountWhere(nums, lambda (n: int) -> bool
    {
        return n > threshold;
    });

    println(big);       // 2

    // Empty parameter list: both parentheses are required.
    greeter: delegate string() = lambda () -> string
    {
        return "hello";
    };

    println(greeter());     // hello
}
```

<Warning title="Mismatched signatures are caught early">
The compiler checks delegate compatibility at the assignment site. For example, assigning a `lambda (a: int) -> string` to a `delegate int(int)` fails with a type error before the program ever runs.
</Warning>
