title: Lambda Expressions
---

## Summary

  A `lambda` expression creates an anonymous function value
  that can be stored in a variable, passed as an argument, or returned from another
  function. The resulting value is a `delegate` whose parameter
  and return types are either declared explicitly or inferred from the lambda body.

## Syntax

  Every lambda starts with the `lambda` keyword, followed by a
  parenthesized parameter list and an arrow that chooses how the return type is determined.
  The body is always a braced statement block.

| Form | Meaning |
| --- | ---
| `lambda` `(params)` `->` `ReturnType` `{` body `}` | Explicit return type. |
| `lambda` `(params)` `=>` `{` body `}` | Inferred return type from the body\'s return statements. |
| `async` `lambda` `(params)` `->` `Task` `{` body `}` | Asynchronous closure; explicit return type is required. |

  A parameter list is a comma-separated sequence of typed parameters in the same form
  used by named methods. A lambda that takes no arguments uses empty parentheses.

// lambda_signature.shard
```csharp
// One parameter with an explicit return type.
lambda (n: int) -> bool
{
    return n > 0;
}

// Two parameters.
lambda (a: int, b: int) -> int
{
    return a + b;
}

// No parameters.
lambda () -> string
{
    return "hello";
}
```

## Parameters / Arguments

  - **Parameter list** — Parenthesized and comma-separated. Every parameter must be written as `name: Type`.
  - **No parameters** — Use empty parentheses `()`.
  - **Return type** — With `-> Type`  the delegate uses that type. With `=>` the compiler infers the return type from the first reachable `return` statement.
  - **Body** — Always a braced statement block. Use `return` to produce a value; a void delegate may omit it.

## Returns

  A lambda expression evaluates to a `delegate` value. Its type is
  determined by context:

  - **Named delegate** — when assigned to a user-declared delegate such as `IntFunc`.
  - **Fabricated delegate** — when assigned to an inline signature such as `delegate int(int)`.
  - **Anonymous delegate** — when no target type is available, the compiler constructs a delegate from the lambda's parameter and return types.

## Exceptions / Errors

  - **Missing lambda keyword** — A bare  `(x) => ...` expression does not parse. The word  `lambda` is required.
  - **Missing parameter type** — Lambda parameters must be explicitly typed with `name: Type`.
  - **Missing arrow or body** — The parser expects either `-> Type` or `=>`, followed by a braced body.
  - **Async lambda without explicit return type**  — `async lambda` must declare `Task` or  `ValueTask<T>`; the `=>` form is not allowed.
  - **Return type mismatch** — The type returned by a `return` statement must match the explicit or inferred delegate return type.
  - **Delegate signature mismatch** — A lambda assigned to a delegate must have the same parameter count, parameter types, and return type.
  - **Null delegate invocation** — Calling a delegate variable that holds `null` throws at runtime.
  - **Captured locals are read-only** — Referencing a local variable from an enclosing scope creates a closure. Captured values are copied into the closure object at the point the lambda is created, and they cannot be reassigned inside the lambda body.

## Remarks

  **Single-expression versus block bodies.** ShardScript lambdas currently
  require a braced statement block. There is no shorthand such as
  `lambda (x: int) -> int x + 1`; even a one-line body must be
  wrapped in `{` `}`.

  **Return-type inference.** When `=>` is used, the
  compiler inspects the body's `return` statements to determine the
  delegate return type. If the body has no return statement, the return type is
  `void`. All return statements in the same lambda must agree on type.

  **Conversion to delegate types.** A lambda is compatible with any delegate
  whose signature matches exactly. This works for named delegates declared with
  `public delegate`, fabricated inline types such as
  `delegate int(int)`, and constructed generic delegates such as
  `Transform<int, int>`. A named method with a matching signature
  can also be assigned directly to a delegate variable without wrapping it in a lambda.

  **Capture rules and closures.** The compiler resolves identifiers in the
  lambda body against the enclosing scope chain. When the lambda references an outer local
  variable, parameter, or `this`, the compiler generates a closure class, copies
  the captured values into it, and rewrites the lambda body to read from the closure object.
  Captured values are copied at the point the lambda is created, so later changes to the outer
  variable do not affect the closure, and the closure cannot reassign the captured variable.

<Info title="Captures are read-only and by value">
Captured locals are copied into the closure object when the lambda is created. The lambda can
  read them, but it cannot assign to them. If you need mutable shared state, store the value in
  a heap-allocated object and capture the reference.
</Info>

  **Asynchronous lambdas.** Prefix the lambda with `async`
  to use `await` inside the body. The return type must be declared
  explicitly as `Task` or `ValueTask<T>`.
  Async lambdas are lowered into the same state-machine machinery as async named methods.

  **VM representation.** A lambda compiles to a static anonymous method whose
  handle type is `Lambda`. At the call site the emitter produces a
  `NEWDELEGATE` instruction that creates a delegate instance pointing
  to that method. Invoking the delegate emits `CALLDELEGATE`, which
  dispatches to the stored target method.

## Examples

  **Named and fabricated delegate types.**

// lambda_delegate_types.shard
```csharp
using stdio;

namespace demo;

// A reusable named delegate type.
public delegate IntFunc(a: int) -> int;

public static func Main() -> void
{
    // Bound to a named delegate.
    fromNamed: IntFunc = lambda (a: int) -> int
    {
        return a + 10;
    };

    // Bound to a fabricated inline delegate type.
    fromInline: delegate int(int) = lambda (a: int) -> int
    {
        return a + 10;
    };

    println(fromNamed(1));   // 11
    println(fromInline(2));  // 12
}
```

  **Inferred return type with the =&gt; arrow.**

// lambda_inferred.shard
```csharp
using stdio;

namespace demo;

public delegate IntFunc(a: int) -> int;

public static func Main() -> void
{
    // The compiler infers 'int' from the return statement.
    adder: IntFunc = lambda (a: int) =>
    {
        return a + 100;
    };

    println(adder(5));   // 105
}
```

  **Parameterless lambda.**

// lambda_parameterless.shard
```csharp
using stdio;

namespace demo;

public static func Main() -> void
{
    answer: delegate int() = lambda () -> int
    {
        return 42;
    };

    println(answer());   // 42
}
```

  **Passing and returning lambdas.**

// lambda_higher_order.shard
```csharp
using stdio;

namespace demo;

public delegate IntFunc(a: int) -> int;

static func Apply(f: IntFunc, x: int) -> int
{
    return f(x);
}

static func Choose(op: int) -> IntFunc
{
    if (op == 0)
    {
        return lambda (a: int) -> int
        {
            return a + 1;
        };
    }

    return lambda (a: int) -> int
    {
        return a - 1;
    };
}

public static func Main() -> void
{
    // Pass a lambda directly as an argument.
    square: IntFunc = lambda (a: int) -> int
    {
        return a * a;
    };
    println(Apply(square, 5));   // 25

    // Receive a function and call it.
    step: IntFunc = Choose(0);
    println(step(10));           // 11
}
```

  **Method-to-delegate conversion.**

// lambda_method_group.shard
```csharp
using stdio;

namespace demo;

public delegate IntFunc(a: int) -> int;

static func Triple(x: int) -> int
{
    return x * 3;
}

public static func Main() -> void
{
    // A named method with a matching signature converts directly.
    f: IntFunc = Triple;

    println(f(7));   // 21
}
```

  **Lambda as a callback.**

// lambda_callback.shard
```csharp
using stdio;

namespace demo;

public delegate Predicate(x: int) -> bool;

static func CountWhere(items: int[], matches: Predicate) -> int
{
    count: int = 0;
    for (i: int = 0; i < items.Length; i = i + 1)
    {
        if (matches(items[i]))
        {
            count = count + 1;
        }
    }
    return count;
}

public static func Main() -> void
{
    nums: int[] = [1, 6, 3, 9, 4];

    // The predicate is supplied inline; no capture is required here.
    big: int = CountWhere(nums, lambda (n: int) -> bool
    {
        return n > 5;
    });

    println(big);   // 2
}
```

  **Async lambda.**

// lambda_async.shard
```csharp
using stdio;
using async;

namespace demo;

public static func Main() -> void
{
    // Async lambdas must declare an explicit Task/ValueTask<T> return type.
    work: delegate Task() = async lambda () -> Task
    {
        println("before");
        await Task.Delay(100);
        println("after");
    };

    Task.Wait(work());
    println("done");
}
```

  **Capturing a local variable.**

// lambda_capture.shard
```csharp
using stdio;

namespace demo;

public delegate IntFunc(a: int) -> int;

public static func Main() -> void
{
    factor: int = 10;

    // The lambda captures 'factor' by value when it is created.
    scale: IntFunc = lambda (a: int) -> int
    {
        return a * factor;
    };

    println(scale(5));   // 50

    // Changing the outer local does not affect the closure.
    factor = 20;
    println(scale(5));   // still 50
}
```

<Warning>
Captured locals are read-only inside the lambda. Reassigning a captured local produces a
  compile-time error.
</Warning>

  Lambda expressions are parsed into `LambdaExpressionSyntax` nodes in
  `ShardScript/src/parsing/SourceParser.cpp`. Capture analysis, closure-class generation,

  `ShardScript/src/compilation/AbstractEmiter.cpp`, and instance-bound delegate invocation
