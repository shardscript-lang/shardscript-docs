## Summary

  ShardScript is an **embeddable, compiled scripting language with strict static typing**,
  implemented in C++20. It is designed to occupy the middle ground between lightweight dynamically-typed
  embeddable languages and heavyweight statically-typed application languages: it offers the ease of
  embedding and rapid iteration of a script engine while catching type, name, and contract errors at
  compile time.

## What problem it solves

  Applications that need user-facing scripting usually choose between two extremes. On one side are
  dynamically-typed languages such as Lua or Python: they are easy to embed, have rich ecosystems, and
  allow writers to iterate quickly. On the other side are statically-typed languages such as C# or full
  C++ plugins: they catch errors early and scale well, but they are heavier to host, slower to compile,
  and harder to sandbox.

  ShardScript targets the gap between those extremes. It is meant for hosts that want:

  - **Compile-time confidence in script code** — typos, missing members, and type mismatches are reported before the script ever runs.
  - **A small runtime footprint** — a custom stack-based virtual machine and a compact bytecode format, not a full language runtime or JIT compiler.
  - **Direct C++ interoperability** — native libraries are ordinary shared libraries (DLL / SO / dylib) that export two well-known entry points, so hosts and third-party authors can extend the language without modifying the compiler.
  - **Familiar syntax** — a C-style grammar with classes, generics, delegates, lambdas, and async/await, lowering the barrier for developers who already know C#, C++, Java, or TypeScript.

## Key ideas

  **Compiled, not interpreted.** ShardScript pays the compilation cost once, ahead of time,
  rather than repeatedly during execution. The result is faster startup of hot paths, earlier error
  detection, and the option to validate scripts during a build step rather than in production.

  **Strict static typing.** Every variable, parameter, field, and return type has a compile-time
  type. Generics, interfaces, classes, structs, and enums are first-class, and overload resolution happens
  at compile time. The language does not fall back to dynamic dispatch to resolve member access.

  **Embeddable by design.** The runtime is a library, not a standalone process. A host
  initializes a `CompilationContext`, compiles source into an
  `ApplicationDomain`, and calls `VM::Run()` on the entry
  point. Native libraries are loaded as shared objects at runtime and register their symbols through the
  same API the standard library uses.

  **Pragmatic, not purist.** ShardScript allows multiple ways to solve common problems when
  each way carries a real ergonomic benefit. `defer` gives deterministic cleanup at
  scope exit, while `IDisposable` lets authors attach custom cleanup logic to the
  same mechanism. Properties, indexers, operator overloading, and extension methods are all available when
  they make an API clearer.

  **First-class native interop.** Script code can call into C++ through native libraries, and
  native code can invoke script methods, read fields, and allocate script objects. This makes ShardScript
  suitable as an extension language for C++ applications where tight integration with existing C++ data
  structures and algorithms matters.

  **Cooperative concurrency.** Asynchronous methods compile into state machines that yield
  control back to the event loop on `await`. There are no OS threads created by the
  language; concurrency is single-threaded and cooperative, simplifying memory safety and avoiding data
  races in script code.

## When to use / When not to use

| Use ShardScript when | Consider alternatives when |
| --- | ---
| You need a script engine inside a C++ application and want compile-time safety for user-written code. | You need a read-eval-print loop (REPL), rapid runtime introspection, or duck typing. ShardScript is compiled and statically typed. |
| You want to ship pre-validated scripts and catch errors during a build or mod-publishing step. | You need a mature package ecosystem, IDE tooling, or language-specific hiring market. ShardScript is a younger, focused language. |
| Your project benefits from C-style syntax, classes, generics, async/await, and native library extensions. | You need direct memory layout control, manual memory management, or zero-overhead abstractions. Use C or C++ directly. |
| You want deterministic cleanup patterns such as `defer` and `IDisposable` alongside automatic garbage collection. | You need multi-threaded parallelism in script code. ShardScript concurrency is cooperative and single-threaded. |
