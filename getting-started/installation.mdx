title: Installation

Getting ShardScript running is a three-piece affair: the `shard` interpreter
  (which includes the compiler, the virtual machine, and the event loop), the
  **Standard Shards Collection** of dynamic libraries, and — for dependency management —
  the `geode` package manager (in development). This guide walks through
  installing the interpreter and shards, configuring library paths, and wiring editors to the language
  server.

## Install from a Release

  Prebuilt binaries are published for Windows and Linux on the
  [0.5.1 release](https://github.com/Rikitav/ShardScript/releases/tag/0.5.1)
  page. The installer scripts below download the matching archive and extract it into a system-wide directory.
  The `SHARDSCRIPT` environment variable is created for tooling convenience, but the
  interpreter itself does not consult it when locating standard shards.

<h3 className="font-space text-lg font-semibold text-text-primary mb-3 mt-6">Windows</h3>

  The PowerShell installer extracts the Windows archive into
  `%ProgramFiles%\ShardScript` and creates the
  `%SHARDSCRIPT%` environment variable.

// install-windows.ps1
```powershell
# Option A: one-liner (run in an elevated PowerShell window)
irm https://shardscript-lang.github.io/shardscript-info/install-shardscript.ps1 | iex

# Option B: download the script first so you can inspect it
Invoke-WebRequest -Uri "https://shardscript-lang.github.io/shardscript-info/install-shardscript.ps1" -OutFile "install-shardscript.ps1"
.\install-shardscript.ps1

# Optional: also add the install directory to your machine PATH
.\install-shardscript.ps1 -AddToPath

# One-liner with PATH registration
& ([scriptblock]::Create((irm https://shardscript-lang.github.io/shardscript-info/install-shardscript.ps1))) -AddToPath
```

  After the script finishes, open a new terminal. The interpreter will be located at
  `%ProgramFiles%\ShardScript\shard.exe` and the standard shards will be in the
  `system` folder beside it.

<h3 className="font-space text-lg font-semibold text-text-primary mb-3 mt-6">Linux</h3>

  The Bash installer extracts the Linux archive into `/opt/shardscript`, symlinks
  `shard` into `/usr/local/bin` so it is on the default PATH,
  and writes `SHARDSCRIPT` to `/etc/profile.d/shardscript.sh`
  for all users.

// install-linux.sh
```bash
# Option A: one-liner (run as root or with sudo)
curl -fsSL https://shardscript-lang.github.io/shardscript-info/install-shardscript.sh | sudo bash

# Option B: download the script first so you can inspect it
curl -fsSL https://shardscript-lang.github.io/shardscript-info/install-shardscript.sh -o install-shardscript.sh
sudo bash install-shardscript.sh
```

  After the script finishes, open a new terminal or run
  `source /etc/profile.d/shardscript.sh`. The interpreter will be located at
  `/opt/shardscript/shard`, the standard shards will be in
  `/opt/shardscript/system`, and the `shard` command will be
  available from any prompt.

<Info title="What the scripts do">
Both installers require root/Administrator privileges because they write to system directories. They
  download `shardscript-0.5.1-windows.zip` or
  `shardscript-0.5.1-linux.tar.gz` from the
  [0.5.1 release](https://github.com/Rikitav/ShardScript/releases/tag/0.5.1),
  extract the archive, set `SHARDSCRIPT` to the install root, and make the
  `shard` command available. The Windows script optionally appends the install root to
  machine `PATH`; the Linux script creates a symlink in
  `/usr/local/bin` instead.
</Info>

## The shard Command Line

  The `shard` binary is the friendly front-end for the
  `ShardScript.Interpreter`. After installation you can run scripts, start the REPL, or
  decompile bytecode. See `The shard CLI` in the Build Your Project section for the full
  command reference.

## The Standard Shards Collection

  ShardScript has no monolithic standard library. Instead the **Standard Shards Collection**
  ships each subsystem as its own DLL — a *shard*. At startup the interpreter auto-loads every
  shard from its `system/` directory, so a script can simply
  `using` the ones it needs. The collection currently includes:

<Tip title="Scope control">
Pass `--no-std` to skip auto-loading the `system/`
  directory entirely, then add only the shards you trust with `-l`. Combined with
  the symbol-injection model, this lets the host control exactly which APIs a script can reach.
</Tip>

## Optional Third-Party Shards

  The framework repository also builds several optional shards in
  `third_party/`. These are not loaded by default and must be referenced explicitly
  with `-l` or copied into the host&apos;s shard search path.

## Library Paths and Package Management

  After installation the standard shards live in a `system/` folder next to the
  interpreter. For details on how the interpreter discovers libraries, how to load extra shards, and the
  planned `%SHARDSCRIPT%` layout, see `Library Search Paths`.

  Dependency management is handled by `geode`, the planned package manager. See
  `Package Management with Geode` for setup instructions and the planned CLI verbs.

## Editor Integration

  ShardScript includes a Language Server (the `lsp` binary, built from
  `ShardScript.LspServer`) that speaks the Language Server Protocol over stdio.
  Editors connect to it like any other LSP server.

<Warning title="In development and Win32-only">
The language server builds and runs on Windows today. Linux/Unix support is not yet implemented, and
  the server is still rough — expect missing diagnostics and incomplete completions.
</Warning>

<Info title="No first-party extensions yet">
There are no packaged Zed, VS Code, or Neovim extensions published today. Each editor is wired to the
  `lsp` binary manually as a generic LSP server; some editors may also need a small
  file-type association for `.shard` files.
</Info>

<h3 className="font-space text-lg font-semibold text-text-primary mb-3 mt-6">Neovim</h3>

  With `nvim-lspconfig`, register a custom server pointing at the binary:

// init.lua
```lua
-- Neovim: register the ShardScript language server via lspconfig
local configs = require('lspconfig.configs')
local util    = require('lspconfig.util')

configs.shardscript = {
  default_config = {
    cmd = { '/absolute/path/to/lsp' },
    filetypes = { 'shard' },
    root_dir = util.find_git_ancestor,
  },
}

require('lspconfig').shardscript.setup( )
```

<h3 className="font-space text-lg font-semibold text-text-primary mb-3 mt-6">VS Code and Zed</h3>

  VS Code needs a client extension to launch an arbitrary server; use a generic LSP-client extension (or
  a tiny generated extension) configured to spawn `lsp` for
  `.shard` files. In Zed, register the binary under the
  `lsp` key in your settings and associate it with the ShardScript language. In both
  cases the server itself is the same `lsp` binary — only the hosting glue differs.

<Tip title="You are set up">
With `shard` installed, the standard shards in `system/`,
  and your editor wired to the language server, you have the core toolchain. Geode and additional SDKs are
  in development. Head to `Hello World` to run your first program.
</Tip>

## Troubleshooting

  - ** `shard` is not recognized after installation. **  On Windows make sure the install directory is on your machine PATH, or restart your terminal after the installer finishes. On Linux run `source /etc/profile.d/shardscript.sh` or open a new shell.
  - **Standard shards are missing.** Verify that a  `system/` folder exists next to the `shard` executable and contains the DLLs or shared objects.
  - **Linux installer fails.** The Bash installer must run as root or with `sudo` because it writes to `/opt` and creates a symlink in `/usr/local/bin`.
  - **Language server does not start.** The `lsp`  binary is separate from the interpreter. Make sure it is built and that the editor configuration points to its absolute path.
