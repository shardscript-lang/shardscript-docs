title: Bytecode and OpCodes
---

## Summary

  ShardScript compiles methods into a flat stream of 16-bit opcodes followed by inline operands. The
  bytecode, together with type shapes and a string pool, forms the `ProgramVirtualImage`
  that the virtual machine executes.

## Syntax

  Each instruction is an `OpCode` value followed by zero or more operands:

| Operand kind | Description |
| --- | ---
| Immediate literal | An integer, double, or boolean encoded inline. |
| Local slot index | The zero-based slot of a local variable in the current frame. |
| Jump offset | A signed byte or instruction offset for branch instructions. |
| String pool index | An index into the module-wide string pool. |
| Symbol reference | A resolved TypeSymbol, MethodSymbol, FieldSymbol, or ConstructorSymbol. |

## Parameters / Arguments

  Operands are decoded by the VM&apos;s instruction decoder. The size and interpretation of operands are
  fixed by the opcode definition. For example, `LOADCONST_INTEGER64` is followed by an
  8-byte signed integer, while `JUMP` is followed by a 4-byte offset.

## Returns

  Most opcodes leave a value on the evaluation stack, store a value into a local or field, or alter control
  flow. The `RETURN` opcode pops the current frame and leaves the return value on the
  caller&apos;s evaluation stack.

## Exceptions / Errors

  - **Invalid opcode.** A corrupted or misaligned bytecode stream may produce an opcode the VM does not recognise.
  - **Stack underflow.** An instruction that expects operands may fail if the evaluation stack does not contain enough values.
  - **Type mismatch.** Although the compiler prevents this, a malformed image may pass the wrong type to a primitive operation.

## Examples

  Use the interpreter&apos;s `-d` flag to disassemble a compiled program:

// disassemble.sh
```bash
shard -d hello.shard
```

  A simple conditional produces bytecode similar to this:

// disassembly.txt
```text
; Offset    Opcode      Arguments
SS_0000:   ldc.bool    false
SS_0003:   jmpf        SS_003F
SS_000D:   ldstr       pool[0]
SS_0017:   call        stdio.println
SS_0021:   jmp         SS_003F
SS_002B:   ldstr       pool[10]
SS_0035:   call        stdio.println
SS_003F:   ldstr       pool[20]
SS_0049:   call        stdio.println
```
